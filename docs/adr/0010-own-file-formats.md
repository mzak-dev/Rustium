# Native `.ruv` format plus our own `.vox` reader and writer

Scenes are saved as `.ruv`: a magic and version header followed by an lz4-compressed postcard encoding of serde types, which keeps the format private to Rustium and versioned explicitly. MagicaVoxel `.vox` is supported by our own parser and writer instead of a crate, converting between `.vox` Z-up and Rustium's Y-up and splitting Shapes larger than 256³ on export. `.vox` cannot be the native format because it limits Models to 256³ and lacks our glass and haze Material properties.

Details of the implementation. A `.ruv` file is the 8-byte magic `RUSTIUMV`, a `u32` little-endian format version, then the lz4 block (with its uncompressed size prepended) of the postcard encoding of a Scene DTO. Saving writes only what is attached to the root: Nodes are renumbered in tree order and unused Shapes are dropped, which is the compaction ADR 0011 left for this point. Voxels are stored per chunk, one byte per voxel. Material graphs are serialized by their own serde derives, so changing their model does not change the container; any such change still bumps the format version. Loading validates every id, the tree shape and the palette references and never panics on damaged input.

On `.vox` import, voxel index `i` is Palette entry `i` (the `RGBA` chunk entry `i - 1`), models are stored in MagicaVoxel's centred frame so `nTRN` transforms map onto Node Transforms, and models shared by several `nSHP` nodes become Instances. Export bakes each placed Model (rotation and Instances included) into world cells, so a Scene with many Instances of one Shape grows on export. `.pal` is the JASC-PAL text format.
